# 历史教训（文学少女 / 弱角 / 恋爱喜剧 三本书实证）

## 最高原则：线索 ≠ 事实
- 外部 LLM 抽取流水线产出的转述内容通常**没有行号**，幻觉率高且可能直接进入报告。本 skill 不依赖这类产物，事实必须来自原文并逐条 grep 核实。
- 下发给子代理的"已核实事实清单"本身也可能错（弱角实跑中 chunk 86 埋设、水泽身份两处被子代理以原文证伪）。清单只防回退，原文永远优先，子代理发现冲突应报告而非盲从。
- 根治方案：agent 自扫主路径——阅读时当场记行号，不做无行号的事前抽取，也就不需要事后清洗阶段。

## SPLIT-PAIR / 实体碎片化
- 弱角：菊池风香(59) 被拆出 菊池风代(4)、菊池茜(1)，报告渲染成三个「女友」章节。判据：别名表重叠（菊池/菊池同学）+ 数量悬殊 + 剧情互斥。
- 文学少女：164 个 female key，彩乃/上野原彩乃/上野原 成片；「泉」同时映射神泉澪/小泉碧（合并风险）。
- 处理：碎片 key 的全部条目并入正主 dump，成品只保留全名正主。

## 串章污染
- 琴吹七濑章混入平安篇剧情（求婚/宫殿/诅咒，实为天野远子线）；远式部章混入远江/话剧/兔子娃娃；美羽章混入菜乃外貌。
- 检测：按角色强特征词全书 grep 跨角色错挂。注意扫描器误报（书内道具《美女与野兽》CD 触发「野兽」），需人工裁决。
- 「已核实事实清单」必须随子代理 prompt 下发，否则子代理会回退上轮修正。

## 幻觉与误删（两个方向都会错）
- 幻觉直通：水户夕歌「圣诞树下埋葬遗体」grep 全本 0 命中；《饱受丧失的女神》等卷名 0 命中。凡 0 命中即删。
- 误删真角色：十望(仙道十望子) 原文 356 命中是真实角色，子代理曾误判「零命中幻觉」删了条目。删条目前必须自己 grep 确认，不得只信直觉。

## 流程教训
- 子代理笔误（日坂美羽→日坂菜乃）会进成品，合并后需全文 grep 人名纠错。
- 章节文件要归位到统一 _sections 目录，避免存成独立散文件。
- 报告压缩只留头部会切掉判定结论：>700 字触发，保留头 240+尾 240。
- 沙箱下文件锁 os.remove 失败会造成 token_tracker 死循环，已是「截断接管」策略。
- API file_content 必须是字符串不是 list。
