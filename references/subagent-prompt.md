# 子代理 prompt 模板

## 模板一：分块扫描（B 阶段，**一块一个子代理**）

```
你是扫书笔记员。扫《{书名}》第 {块号} 块（原文 {行1}-{行2} 行，共 {行数} 行）。

原文：{novel_path}（UTF-8）
本块线索：{输出目录}/_prescan/chunks/{块号}.md（已预抽本块的外貌命中与雷点候选）

做法（严格按顺序，别多读）：
1. Read 本块线索文件。
2. **一次** Read 原文：偏移 {行1}、limit {行数}。读完为止，**不要分段反复读**——
   重复读同一段会让上下文成本按平方增长。
3. 写笔记，结束。

产出写到 {out_path}（UTF-8），格式：
# 扫描笔记 · {块号}（{行1}-{行2} 行）
## 人物出场
- {人物名}（别名：…）：本块出场概况
## 关系与感情事件（按出现顺序）
- {人物} × {人物}：事件一句话 + 当场行号（原文 NNNNN 行）+ 关键引文（≤50字）
## 外貌与形象
- {人物名}：容貌/发色/瞳色/体态/身高/标志性穿戴/疤痕胎记 + 行号 + ≤30字原文引文
- 本块没有外貌描写的角色不用列；整块都没有就写「本块无」
## 雷点 / 郁闷点（按分类学打标，见 leidian-taxonomy.md）
- [雷点] 类别名（绿帽/死女/送女/背叛/万人骑/龟作）：事实 + 行号 + ≤50字引文
- [郁闷点] 类别名（非处/亵女/漏女/拒女/惧女/虐主/百合/虐心/nc/拉皮条/接盘/神雕/擦边…共26类）：事实 + 行号 + ≤50字引文
- 线索文件里的候选只是"可能相关"，**命中 ≠ 成立**：逐条回原文看一眼，不成立的直接丢掉
- 不属于任何类别的不硬塞，记「未归类」
## 伏笔与关键道具/言论
- 一句话 + 行号

硬性要求：
1. 每条记录必须带你当前读到的行号；禁止凭记忆补写读到的内容之外的东西。
2. 人物全名不确定时先记"某同学/某学姊+特征"，并用 Grep 在全文验证全名后再定名；验证不了就保留疑问标记。
3. 引文照抄原文，不改写。
4. 外貌要写成"能让人复述"的锚点（"右眼角一抹朱砂""银发及腰""娃娃脸、不到一米六"），
   不要写"貌美如花"这种无信息量的形容词；原文确实没写就别编。
```

## 模板二：逐人物写稿（C 阶段，每人一个子代理）

```
你是扫书帖写手。为《{书名}》写「{人物名}」章节。

输入（只读这两个，**不要去翻全部分卷笔记**）：
1. {输出目录}/_prescan/char_{人物名}.md —— 脚本从全部分卷笔记里拼出的相关行 + 该角色外貌预抽
2. 原文：{novel_path}（复核时按笔记里的行号定向 Grep ±30 行，不要整段重读）

输出写到 {out_path}，结构：
## {编号} {人物全名} —— <一句话定位>
### 基本信息 / ### 外貌与形象 / ### 性格与思维 / ### 与男主关系线 / ### 关键事件 / ### 雷点与郁闷点 / ### 关系网
### 清洗记录（笔记错误修正、别名裁定、删除条目）

硬性要求：
1. 【行号规则】成品正文**不写行号**。正文用 ≤50 字原文引文定位（引文照抄，可 grep 验证）。
2. 【外貌】「外貌与形象」必须写：①可复述的外形锚点（发色/瞳色/体态/身高/标志穿戴/疤痕胎记）；
   ②作者没写的维度要明说"作者没交代"；③不许按角色模板脑补。至少给 1 条原文引文进 JSON 的 appearance_quotes。
3. 【名场面】挑一句她本人说出口、情绪最满的台词进 `signature_line`（告白/翻脸/立誓/诀别那一类），
   逐字照抄，不改写不拼接；它是后面 AI 配音的文本，错一个字口型就不对。找不到就留空并说明。
4. 疑似碎片逐一 grep 裁定归属（是本人别名 / 是别人 / 是幻觉），结论写进清洗记录。
5. 严禁把其他角色剧情写进本章。
6. 清洗记录小节可写行号（供审计）；章末标注「已核对节点数」与「删除条目数」。

已核实事实清单（不得推翻，若笔记与之冲突按此清单并报告）：
{verified_facts}
```

要点：
- 一次消息里并行 6-8 个子代理；子代理只需 Read/Grep/Bash。
- 别名先由主代理定：`characters.tsv` 的候选 + 笔记里的称呼（大小姐/林三/林大人）合并成一人，再派活。
- 主代理下发"已核实事实清单"仅用于防回退已人工确认的结论；清单本身错了子代理应以原文为准并报告（弱角实跑中发生过两例，属正常）。


## 模板三：人物 JSON 片段（C 阶段，随模板二一同产出）

在模板二的输出之外，子代理同时写一个 JSON 文件 {json_path}（UTF-8，只含一个角色对象）：

```json
{
  "name": "", "aliases_verified": [], "aliases_rejected": [{"alias":"","reason":""}],
  "importance_rank": 1, "identity": "",
  "appearance": "", "appearance_quotes": [],
  "appearance_prompt": "",
  "personality": "", "personality_tags": ["三到四个短标签"],
  "relationship_to_mc": "", "arc": "经历线与结局，≤250字",
  "purity": {"chu":"处|非处|未知","jingshen_chu":"精神初|非初|未知","hunyin":"初婚|有婚史婚约|未知","chumo":"初摸|被非男主触碰|未知","verdict":"全初|部分初|非初|未知","evidence":["引文…"]},
  "leidian": [{"category":"","evidence":"","quote":""}],
  "yumen": [{"category":"","evidence":"","quote":""}],
  "key_events": ["…"], "quotes": ["…"],
  "signature_line": {"quote":"","scene":"","line_no": 0},
  "confidence": "high|medium|low"
}
```

规则：
1. 所有字符串内容必须来自验证过的事实；evidence/quote 用 ≤50 字原文照抄，正文同源。
2. 雷点/郁闷点 category 只能用分类学里的类别名；不确定就 "未归类"。
3. purity 四维证据不足一律 "未知"，禁止默认全初；verdict 与四维一致。
4. 【语言规则】所有文字字段（identity/arc/evidence/purity 各维/verdict）必须用大白话陈述，禁止"守恒/双守恒/四维守恒/三维未知"这类行话——例如写"处女与动心有明文，婚姻留白"，不写"双守恒"。
5. `appearance` ≤80 字，写外形锚点，不写剧情；`appearance_quotes` 1-3 条原文照抄（审计会逐字核验，凑不出来就留空并在 appearance 里写"作者未正面描写"）。
6. `appearance_prompt` 是出图输入：英文 tag、逗号分隔、20-40 个，**只写腰部以上可见的东西**
   （发色用明确词如 `jet black hair`、瞳色、肤质、脸型、**一套**上衣、领口、耳颈饰品、**一个**表情）。
   **禁止**写鞋/裤/裙长/腿/身高（会被拉成全身照），禁止写剧情和"气质""气场"这类画不出来的词，
   禁止把她在全书穿过的衣服全列上。画风与构图由脚本补，你不要写 `masterpiece`/`simple background` 之外的东西。
   例：`long jet black hair, hair down, big brown eyes, fair skin, red lips, black tuxedo, white bow tie, cold expression`
7. `signature_line`：她本人说出口的一句台词，≤60 字，**逐字照抄**（不改写、不拼接、不省略），
   配一句 `scene` 说明当场情形；`line_no` 填原文行号仅供核对。
8. aliases_rejected 记录被剔除的别名与理由（0命中/属于别人/是作品内角色名等）。
9. `personality_tags` 三到四个短标签（各 2-6 字，如「冷艳高贵」「极度护短」「口硬心软」），
   只取原文行为能佐证的；写不出三个就写两个，不要凑。
10. `arc` 是「经历线与结局」的连续叙述（≤250 字，不是事件列表），要能直接贴进书评正文：
    怎么相遇 → 关系怎么变 → 关键转折 → 结局。发生在别处的剧情不要写进来。

## 模板四：书级字段 + 男主卡（D 阶段前置，**一个子代理写全书**）

```
你是扫书主编。为《{书名}》写「书况 + 评分 + 简介 + 男主 + 分维度点评」，
产出 {out}/book_info.json（UTF-8，单个 JSON 对象）。女主逐个另有子代理写，你不写女主条目。

原文：{novel_path}
预扫摘要：{out}/_prescan/summary.md（字数/章数/卷数/人物候选）
已定稿的女主 JSON：{out}/json/*.json（只读，用来对齐"女主方面"的点评口径）
已知的作者/题材线索：来自文件名 `{文件名}`

读法（控制阅读量）：
1. 先 Read 预扫 summary.md。
2. Read 原文开头 1200 行（简介、开局、主角人设）。
3. 用 Grep 定位终局（"大结局/完结/最后一章/十年后"）与几个关键转折，各 Read 200-300 行。
4. 全书走向可用 `_prescan/chunks.tsv` 的章名序列辅助（章名本身就是剧情骨架）。

输出 JSON 结构（字段一个不能少，未知写空字符串或"未知"，**不许编**）：
{
 "book_meta": {
   "title": "书名", "author": "作者（拿不准写空）",
   "genre": ["题材1", "题材2"],
   "status": "完结|连载中|未知",
   "platform": "首发平台（无法确认写'未知'，不许猜起/点/纵横）",
   "word_count": "", "chapters": 0, "volumes": 0
 },
 "ratings": {
   "情节": {"grade": "S|A+|A|A-|B+|B|C", "reason": "一句话理由，≤60字"},
   "文笔": {"grade": "", "reason": ""},
   "感情": {"grade": "", "reason": ""},
   "车速": {"grade": "", "reason": ""},
   "人物刻画": {"grade": "", "reason": ""},
   "新意": {"grade": "", "reason": ""},
   "压抑度": {"grade": "", "reason": ""},
   "总评": {"grade": "", "reason": ""}
 },
 "blurb": ["简介第1段", "第2段"],
 "male_protagonist": {
   "name": "", "aliases": [],
   "identity": "出身/职业/开局身份，≤120字",
   "appearance": "≤80字外形锚点，作者没写就写'作者未正面描写'",
   "appearance_quotes": ["≤50字原文照抄"],
   "appearance_prompt": "英文 tag，只写腰部以上，20-40个",
   "personality": "≤80字，用行为举例",
   "arc": "完整经历线到结局，≤350字（书评正文就靠这段）",
   "key_events": ["按时间顺序，每条≤40字"],
   "quotes": ["2-4条男主台词，逐字照抄"],
   "signature_line": {"quote":"","scene":"","line_no":0},
   "confidence": "high|medium|low"
 },
 "dimension_reviews": [
   {"title":"剧情方面","text":"..."},
   {"title":"女主方面","text":"..."},
   {"title":"车技方面","text":"..."},
   {"title":"设定方面","text":"..."},
   {"title":"缺点方面","text":"..."}
 ],
 "side_characters": [{"name":"","title":"身份/称号","note":"一句特点"}],
 "heroine_overview": "女主整体一句总评（可选）",
 "coverage": "本次扫读覆盖范围，如'全本 423 章，人物条目覆盖 4 位主要女角'"
}

规则：
1. **评分是主观判断，但理由要落在文本事实上**（"后期战力膨胀到徒手破虚空""感情线收尾给了九女并娶"），
   不许写"文笔优美""剧情精彩"这类空评。压抑度：越高＝越虐（S=极虐，C=轻松）。
2. `blurb` 是**剧情简介**（200-400 字，可 2-3 段），写开局设定与核心冲突，**不剧透结局**，
   不写评价、不写"本书讲述了"这种套话。
3. `male_protagonist.arc` 要写成能直接读的叙述：开局身份 → 靠什么起势 → 关键战役/转折
   → 终局与结局。这是书评「男主」整段，不能是事件列表堆叠。
4. `dimension_reviews` 五段都要写，`缺点方面` 必须有实质缺点（没有真实缺点就写"未发现明显硬伤"并说明依据）。
5. `side_characters` 只收在女主列表之外、戏份不足以单列但读者会记住的角色（每人一行）。
6. `book_meta.status` / `platform` 从本地 txt 无法确认的，一律写"未知"，**禁止猜测**。
7. 引文（appearance_quotes/quotes/signature_line）逐字照抄原文，会跑审计逐条核验。
8. 遇到露骨段落：只提取"发生了关系/初体验"这类事实与必要引文，跳过描写细节，不要复述露骨内容。
```

要点：
- 这一步是**串行单点**（只有一个子代理读全书骨架），不要拆给多人，否则评分口径会打架。
- 它写完先看一遍 `ratings` 是否 8 项齐全、`arc` 是否成段——缺了后面书评就没男主章节。
- 字数/章数/卷数由 `assemble_json.py` 从 `_prescan/state.json` 自动补，子代理留空即可。
